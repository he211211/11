看得见的声音—智能发音学习平台
团队分工与排期方案


评判维度 ：技术创新性、落地完整性、社会价值、材料打磨度、答辩表现。因此分工兼顾” 产品研发” 与” 冲奖配套” ，不能只盯写代码。
配置：组长 1 人 + 后端 3 人 + 前端 2 人 + 大模型 3 人（三人组）+ 支撑 2 人 +测试 1 人，共 13 个岗位（A/D 简俊腾一人双岗；何丙轩、莫奕泓、姚振锐、周安来、梁熙贤自开学第 1 周到岗）。



第 一 节 团队总览

前端	2	简俊腾 (D)、李剑锐 (E)：核心学习流程可视化、创新交互（SVG/Canvas/构形动画/3D）

第 二 节 组长（1 人）——技术 + 项目总控
角色：架构师 + 项目经理 + 答辩主辩手
职责：
•  整体技术架构设计、技术选型拍板， 统一模块接口规范（FastAPI  的 RESTful  / WebSocket API + 前端类型对齐）。
•  制定里程碑，每周同步进度、风险管控。
•  统筹申报书、商业计划书、 PPT 的逻辑主线，确保” 技术亮点” 与” 叙事” 一致，并贯穿需求文档强调的创新点。
•  对外对接指导老师、协调资源，主答辩。
•  兜底核心难点（3D 声道建模、评分算法、版本管理一致性）亲自攻坚。
关键能力：全栈视野 + 表达能力强。



第 三 节 后端（3 人）
后端 3 人按” 分析引擎 / 深度学习 / 服务与 CMS” 纵向切分。

3.1  成员 A ——语音分析引擎负责人（简俊腾）
•  负责 audio_analyzer.py（Librosa / Pitchy 声调曲线、基频 F0 提取、LPC 共振峰 F1/F2）、 feedback_engine.py（四步反馈规则引擎）。
•  实现 POST /api/audio/analyze、POST /api/feedback、POST /api/quality（录音质量检测）等核心接口。
•  攻关：声调曲线对比算法、综合评分权重模型、 F0/F1/F2 声学特征与口腔构形的关联建模。

3.2  成员 B ——深度学习 / ASR 负责人（李嘉怡）
•  负责 dl_analyzer.py（从 audio_analyzer.py 拆出；采用更先进的 Wav2Vec2 / HuBERT / Whisper 对比选型，建议以 Whisper 微调中文发音错误检测为主， 兼顾轻量化部署）。
•  POST /api/asr/load 模型加载、发音错误检测（误读/漏读/声调错位定位）；声学模型微调与推理性能优化（ONNX 导出 / MPS-CPU 兼容 / 懒加载 / 失败降级）。


•  攻关：发音错误检测即” 声母/韵母/声调闭环”，是技术创新性的硬核支撑； 与大模型三人组解耦——B 产出” 结构化发音诊断”，大模型三人组负责” 自然语言纠音话术生成”。

3.3  成员 C ——服务基建 + CMS / 数据库（胡鹏伟）
•  负责 database.py（SQLite，7 表；可升级 PostgreSQL  以支撑版本管理与并发）、 /api/units、/api/admin/*、/api/media（内容录入/审核/发布/下架/版本管理 +操作日志）。
•  实现需求文档关键的 CMS 工作流引擎：录入 → 审核 → 版本可追溯（版本标识、回退、日志）、普通用户录音默认只服务本人不进样本库。
•  结果版本化（规则/模型结果留版本记录， 固定样本可复现对比）； 为大模型三人组（苏/姚/周）预留 CMS 智能审核接口（如自动初筛异常录入），但模型推理本身由三人组独立实现。
•  兼 API 网关规范、依赖治理、容器化部署。




第 四 节 前端（2 人）
前端 2 人按” 核心学习闭环” 与” 创新可视化交互” 切分，技术栈在原有 Vue3+TS+ECharts基础上，按需求文档新增 SVG 交互图表、Canvas 构形动画、Web Audio API、In-
dexedDB。

4.1  成员 D ——核心学习流程 + 数据可视化（简俊腾）
•  负责 LearningView.vue、FeedbackView.vue、ComparisonView.vue（P03/P04/P06）。
•  技术栈落地：
–  录音质量检测 +  四声分析 ：MediaRecorder + 后端 Python 分析。
–  可视化曲线 +  四步反馈 ：ECharts/Canvas + 规则引擎（feedback_engine）。
–  多次录音比较 + 趋势分析：IndexedDB（本地）+ 后端数据库（学习档案、版本记录）。
•  用户直接感知” 打分反馈” 的主界面，体验好坏决定评委第一印象；当前 ComparisonView为 mock 必须接真实对比。


4.2  成员 E ——创新可视化交互（李剑锐）
•  负责发音地图/库（PronunciationMap.vue、PronunciationLibrary.vue，P01/P02） +  口腔构形动画页 + 与大模型三人组联动的智能反馈呈现。
•  技术栈落地（需求文档创新点 + 靠拢先进方案）：
–  声母/韵母/声调关系可视化 ：SVG 交互式图表 + 分类筛选（可结合 D3.js 增强交互）。
–  构形动画 + 标准音频 +  分步练习 ：Canvas 动画 + Web Audio API （参考VocalTractLab  口腔声道）。
–  3D 声道建模 ：Three.js + GLTF，与实时录音联动（ws/audio-stream）， 视觉冲击力是国赛加分项。
–  大模型能力前端呈现：调用大模型三人组提供的本地模型服务， 把”  自然语言纠音建议” 以流式打字机效果、卡片分步练习呈现， 让创新点可被评委直观感知。
•  攻关： 口腔构形动画与 F1/F2 声学特征的对应表达（需求文档 P 段”  口腔开放与F1/F2”）。



第五 节 大模型三人组——苏合群、姚振锐、周安来
角色：本地开源大模型推理 + 智能纠音/CMS 智能审核，三人协作推进、不设明确边界；对外接口由苏合群牵头，组直接汇报给组长，不与后端 B/C 职责耦合。每周组会认领组任务，组内轮值主办、互备互查。
技术路线：本地部署开源小模型（如 Qwen2.5-几 B  /  Qwen2.5-Coder），用Ollama / llama.cpp / vLLM 本地推理，体现”  自主可控、离线可跑、数据不出域”；三人共同掌握部署、提示词与评测三条线。
职责：
•  智能纠音话术生成：消费后端 B 产出的” 结构化发音诊断（声母/韵母/声调错误） ” , 用本地 LLM 生成自然语言四步反馈（现象 → 环节 → 提示 → 练习），替代/增强原 feedback_engine.py 的纯规则模板，使反馈更拟人、可解释。
•  CMS  智能初筛：为 C 的 CMS 工作流提供” 录入内容自动初审/异常标注” 能力（如发音单元描述是否规范），减轻人工审核负担，体现”AI + 工作流” 系统创新。
•  前端智能交互后端：以轻量 API/MCP 向前端创新交互页供给流式纠音建议， 向管理员页供给智能审核结果。


•  评测脚本：编写大模型输出质量评测脚本（与梁熙贤、何丙轩的测试体系衔接），保证离线推理结果稳定可复现。
•  攻关：提示词工程（结构化诊断 →  自然话术）、本地模型量化（4-bit/GGUF）以保障比赛机上的推理速度与显存可控。
关键能力 ：对大模型本地化部署、提示词工程、轻量服务化有经验或强学习意愿；三人互补、轮值深耕各条线。

2.  社会价值：突出 ” 助力方言区/听力障碍/对外汉语” 等场景，组长在材料中强化。
3.  演示稳定性：梁熙贤的测试覆盖” 现场网络差也能跑” （IndexedDB 本地兜底 + 大模型本地离线推理，不依赖外网 API），何丙轩验收把关，答辩 demo 不能翻车。

7.  组长答辩：金牌答辩看主讲人表达能力， 组长需提前 2 周演练，并熟记各成员模块的技术细节以应对提问。
